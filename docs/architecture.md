# Architecture

The default video pipeline is a deterministic Canvas batch renderer. An optional MilkDrop path runs Butterchurn in a private headless browser and composites its evolving background beneath the same Canvas foreground before MP4 encoding. The separate local WebGL visualization preview combines the flowing Resonance geometry with generated material maps and music-driven lighting, using a different mesh density and layer set.

## Boundaries

### 1. Decode

[`src/audio/decode.ts`](../src/audio/decode.ts) asks FFmpeg for mono and stereo, 24 kHz, 32-bit floating-point PCM. The established mono decode stays byte-identical and supplies motion features and the decoded-PCM hash, so container metadata does not affect the automatic visual seed. A parallel stereo decode preserves separate left and right samples for the spectrum readouts.

### 2. Analyze

[`src/audio/analyze.ts`](../src/audio/analyze.ts) calculates fixed-rate feature frames. A 2048-sample Hann window feeds an in-repository radix-2 FFT. Logarithmic frequency bands and track-wide percentile normalization turn source-dependent magnitudes into stable `0..1` control signals.

The analysis stage owns signal processing and temporal smoothing. RMS attack and release coefficients account for elapsed time, preserving their response across output frame rates. Analysis defaults to 60 feature frames per second to match the 60 fps output. Each new frame includes `spectrumLeft` and `spectrumRight`, normalized against one shared track maximum after logarithmic compression; shared headroom prevents sparse, hard-panned tones from clipping both channels to the same level. Mono motion features retain their existing percentile normalization. Analysis caches remain version **2**; older versions and caches sampled at another output frame rate must be regenerated. Version-2 mono caches still load: [`src/audio/stereo.ts`](../src/audio/stereo.ts) fills their missing stereo spectra from verified source audio before export, preserving their mono features and song identity. The loader requires both channels on every frame if present and validates all values; JSON is bounded to 192 MiB and ten million scalar feature values.

[`src/audio/onsets.ts`](../src/audio/onsets.ts) extracts shared onset events from normalized analysis and queries them by absolute time. Flat or clipped peaks produce one event at their leading edge; the initial FFT comparison against silence is excluded. The conductor uses fixed-time event envelopes for rhythm activity and beat decay, and the hit plan ranks these same events.

### Highlight selection and metadata

The `clip` CLI subcommand shares decoding, analysis and `renderVideo()` with ordinary renders. [`src/audio/clip.ts`](../src/audio/clip.ts) exposes the pure `selectClip(analysis, options)` API. Prefix integrals of bass-weighted energy allow time-based pre-hit, attack and post-hit windows to be scored in linear time. A candidate needs a sharp rise and sustained contrast; isolated impulses and gradual intro ramps are rejected. Context weighting favors usable lead-in and post-drop music. With no distinct drop, the highest mean-energy window wins, with deterministic earliest ties.

`ClipSelection` records source `start`, `end`, `duration`, optional `drop` and `dropOffset`, a selection `reason`, and a heuristic `score`. Default duration is 30 seconds and lead-in three seconds. Manual `drop` overrides the detector. Frame-aligned starts and durations keep normal delivery within the requested limit; short sources retain their available audio and the render core pads only a fractional final video frame. A drop near EOF shortens the clip while preserving lead-in. Selection never slices the analysis, so the visual renderer continues on the original absolute song timeline.

[`src/audio/metadata.ts`](../src/audio/metadata.ts) reads structured FFprobe tags using an argument array. Explicit CLI text and config text take priority, then format/audio-stream tags supply normalized title and artist values; album artist is a fallback. Clip export requires an artist credit. The portrait layout retains the same large credits and safe zones as full-song rendering: supplied artwork sits beside left-aligned title and artist text in a centered group, while text without artwork remains centered.

`clip --dry-run` validates the analysis/source relationship and prints the selection, delivery profile, frame-quantized duration and effective fades as JSON without starting an encoder. The clip profile defaults to native 1080×1920 at 60 fps and final encoding, with independent 0.35-second entrance and three-second exit fades. Near source boundaries, the entrance is capped at the drop offset and the exit leaves a brief full-volume post-drop hold; dry-run and encoding receive the same effective fades. Normal render defaults remain unchanged.

### 3. Plan and render

[`src/render/renderer.ts`](../src/render/renderer.ts) draws the **Resonance** preset using named seeded streams for the harmonic filaments, the no-cover nebula lobes, the ember bokeh, the dither sheets and the spectral-ribbon plan, whose direction also sets the camera's roll direction. Object properties are generated once or derived from an event's stable analysis-frame index. Positions are analytic functions of absolute time and integrated musical time, so frame `n` is independent of frames `0..n-1`. Every per-frame signal (scene dynamics, raw and blended motion, the raw kick, the hit momentum, section level, presence, conductor state, effects, choreography, grade, lights, camera pose, filaments, live hits and the signal band) is derived once per frame into a `FrameState`; captures of the sculpture for surface fragments and frozen ghosts build the same state for their own capture time. An optional `profiler(stage, surface)` hook is called after each of the render stages listed below and never touches pixels; it exists so a flush-based profiler can time stages that `@napi-rs/canvas` rasterises lazily.

[`src/render/music-motion.ts`](../src/render/music-motion.ts) exposes `deriveMusicMotion(analysis, time)`. It derives independently normalized bass, mid and treble envelopes, bass and treble transient pulses, and a sustained energy envelope. Attack and release rates use elapsed seconds. Cached scalar prefix integrals and analytic integration inside each analysis interval produce `slowTime` and `fastTime`; motion accelerates with musical energy without accumulating mutable render state or changing position abruptly. Direct seeks and sequential rendering follow the same path, and transient pulses never precede their analysis timestamps. The raw `bassPulse` (a one-frame attack with a 160 ms decay) reaches the mono signal levels used by the embers; everything with mass follows the kept hits through [`src/render/momentum.ts`](../src/render/momentum.ts), and the raw band envelopes keep their section contrast in the picture.

[`src/render/momentum.ts`](../src/render/momentum.ts) turns the cached hit plan into four pushes of different mass. Each is the sum over the live hits of the hit's push (its size; a third of it for a hat) through the kernel `(age/τ)² · e^(2 (1 − age/τ))`: zero at the hit with zero velocity, one at τ, below 0.01 by 5τ. τ is 140 ms for the cover room, 110 ms for the camera zoom, 100 ms for the full-frame warm lift and the core burst, 80 ms for the sculpture's fold, the key light, the skin and the embers' swell, and 45 ms for the bloom smear and the bloom's glow and saturation accents (`attack` in the blended motion). Hits taper out of the kernels over the last 120 ms of their lifetime, so nothing steps when one leaves. The sculpture, its skin and the reflected strip light read the analysis frame through `smoothedFrameAt()` in [`audio-field.ts`](../src/render/audio-field.ts): its spectrum is the existing 32 causal material-band envelopes (32 ms attack, 22 ms inertia, 120-400 ms release) resampled to the analysis band count, with bass, mid and treble re-derived from it, while onset, loudness and the waveform stay per-frame.

[`src/render/scene-dynamics.ts`](../src/render/scene-dynamics.ts) adds six independent spectral envelopes and momentum clocks through `deriveSceneDynamics(analysis, time)`. Each tier reads a fractional interval of the analyzed spectrum. A shared causal peak reference with an eight-second release and a gain ceiling of five reveals quiet passages while preserving the stronger low-frequency response; later analysis frames cannot rescale earlier tier states. An attack/release envelope drives a second momentum filter. The returned `energy` is that momentum-smoothed value, so spatial scale, light and opacity have the same inertia as motion speed. The cascade and its integrated area are evaluated analytically at each tier's delayed timestamp; cached prefix states make direct, reverse and sequential seeks agree.

| Tier | Frequency focus | Delay | Envelope release | Momentum | Typical role |
| --- | --- | --- | --- | --- | --- |
| `drift` | Deepest lows | 180 ms | 8 s | 3.2 s | Slow palette breath, ember sway and camera drift |
| `cloud` | Lows and lower mids | 140 ms | 3 s | 1.05 s | Bloom breadth and turning smear, camera roll |
| `body` | Bass | 80 ms | 0.7 s | 0.22 s | Sculpture, camera breathing and the embers' rise |
| `detail` | Mids and upper mids | 40 ms | 0.3 s | 0.085 s | Blended mid envelope: tube shape and flow |
| `spark` | Upper spectrum | 15 ms | 0.12 s | 0.028 s | Blended treble envelope: fine ripples |
| `impact` | New bass-supported hits | 25 ms | 1.2 s | 0.1 s | Floor under the kick for the bloom pulse and skin light |

The impact tier excludes the initial FFT comparison and requires positive raw bass flux or a new onset supported by bass; normalization recovery during a held note cannot manufacture a hit. Baseline motion starts at time zero even though musical contributions are delayed. Slow tiers can continue gathering after a burst while faster tiers are already releasing. Tests check distinct latency, momentum-to-clock consistency, frame-rate independence and independence from later analysis frames. These controls complement the existing `MusicMotion` transport and conductor rather than replacing their geometry and section-level roles.

[`src/render/scene-optics.ts`](../src/render/scene-optics.ts) blends the two in `inertialMusicMotion`: the smoothed tiers set the ceiling while the raw band envelopes keep their section contrast (bass `0.30 + 0.70 × raw` on the body tier, and so on), and the kick is the larger of the raw pulse and half the impact tier. `sceneCameraAt(dynamics, phase, direction, kick, section)` supplies a bounded camera drift, roll (under four degrees) and breathing zoom `1 + body × 0.05 + kick × 0.05 × (0.5 + 0.5 × section) + section × 0.05 + cloud × 0.012 + drift × 0.006`, shared by the live sculpture, both emission passes and every capture pose; `sculptureFit(section)` gives the share of the safe graph the sculpture may fill, `0.66` in quiet passages to `0.96` at peaks. Kick and section are geometry and are never capped. `drawAtmosphericBloom` turns the quarter-resolution emission field into three copies: a broad saturated blur whose alpha and radius follow the cloud tier, one enlarged, slowly rotated copy that pulses with the larger of the impact tier and the kick, and a fine sharp halo; their summed alpha stays under one so dense emission keeps its pigment instead of clipping to white. A final screen-space mask protects the credits after filtering. `ringReachWithin` computes how far an ellipse from the sculpture's core can grow under the current pose and still stay inside the graph clip, so the hit rings dissolve inside the reserve instead of being cut flat.

[`src/render/music-effects.ts`](../src/render/music-effects.ts) maps the blended motion through `deriveMusicEffects(motion, lowFlash, dynamics?, warmth)` to a palette phase, saturation and glow. `warmth` (the conductor's track-relative smoothed centroid) anchors the phase two swatches along the ring, the band energies nudge it a little further and a slow breath on the drift clock keeps it alive; the phase selects source swatches and never rotates the artwork's hues. `frequencyResponse(energy, bandPosition)` gives low frequencies greater spatial influence than equal high-frequency amplitudes. Only the light attack shrinks under lowFlash.

[`src/render/resonance.ts`](../src/render/resonance.ts) builds 72 flowing filaments with 241 points each, including the repeated closing point. The slow musical clock changes the aperture and tube proportions from an open ring toward an orb, introduces a three-lobed radial contour and bends the volume into a plasma knot. Opposing horizontal/vertical stretch and broad 3D precession change its silhouette as it turns through perspective. Blended bass energy and the causal bass pulse drive the largest folds; mids have a smaller influence on tube shape and flow; treble energy and pulses add fine ripples on the fast clock. Frequency-weighted spectral bands and low waveform harmonics supply further detail. Strand-dependent displacement is periodic in its poloidal angle, so the last and first mesh rows join without a spectrum-driven seam. Each point carries its poloidal band position, which the renderer uses to draw bass positions in the cover's warm pigment and treble positions in the cool one. The projected sculpture is fitted as a whole after accounting for the exact scene camera; the caller's `fit` (section × presence) makes the object small and wispy in quiet passages and close to the full reserve at peaks, with a smooth bounded enlargement for compact poses. Filament alpha rises from 0.24 at rest with drive, peak and the capped beat. Point depth separates front and back drawing passes. Fast tracers follow the front contours; local energy controls their brightness. There is no contour echo and no previous framebuffer.

[`src/render/conductor.ts`](../src/render/conductor.ts) builds a cached, track-relative energy profile and turns local contrast, rhythm activity, build/drop trend, and beat impulses into continuous ambient, drive, peak, form, motion and chapter controls. It uses bounded analysis windows, including deterministic look-ahead, rather than mutable playback state. `deriveSectionLevel(analysis, time)` is the loudness of the surrounding five seconds on the track's own scale (a symmetric windowed mean over prefix sums, so the picture leans into a drop about 2.5 s early and relaxes after it); `VisualState.warmth` is the spectral centroid smoothed over the same window and stretched over the track's own p10..p90 range (with a minimum span, so a flat track reads as neutral); `presenceAt(time, duration)` is how much of the sculpture is there: it arrives over the first ~3 s and steps back to 45% over the last 14 s, both windows shrinking on short tracks. A pure choreography map crossfades layer weights across musical sections. `LOW_FLASH_TRANSIENT_CAP = 0.5` is the one place the lowFlash policy lives: geometry is never capped, luminance transients are capped at this level, and every consumer reads the constant.

[`src/render/hit-plan.ts`](../src/render/hit-plan.ts) replaces the former onset sparks, beams, shockwaves and supernovas with one cached plan per analysis. Every onset event is sized by `0.5 × strength + 0.5 × rank` among the onsets within ±4 s, so among a run of clipped onsets the hits that are loud for their neighbourhood still stand out and an intro tap scores lower than a drop kick; non-maximum suppression with a 0.34 s refractory (`HIT_REFRACTORY`, so at most `FLASH_MAX_RATE` ≈ 2.9 hits per second) keeps the strongest hit of every cluster. Each kept hit records the onset frame's bass share and a kick/hat label split at the median bass share of this track's hits with a narrow crossover. `hitEventsAt(analysis, time)` returns the hits younger than `HIT_LIFETIME` (0.7 s), newest first and at most three, identically for direct and sequential seeks; `hitRingAlpha` fades ring light with age and, under lowFlash, ramps it in over 50 ms and caps it at 0.45; `hitRingReach` eases the ring's radius out toward the clip fit. The renderer draws a ripple ring from the object's core, behind the sculpture, in the warm pigment for kicks and the cool one for hats (pigment source-over on a cover, screen over the nebula, plus a wider emission copy for the bloom). Every ring is its own ellipse: `hitVariation(seed, hit)` fixes its diameter (0.82-1.18), aspect (0.78-1.22), stroke width (0.7-1.4), tilt (±0.3 rad) and the direction and share of the radius (5-14%) it drifts as it spreads. As it grows it blurs, as a stack of up to seven widening strokes with Gaussian weights (a real canvas blur on a 1080p stroke cost ~12 ms per ring), and the pigment copy fades as (1 − eased)^1.5 while the bloom's diffuse copy carries the end, so the ring is lost in the room before its lifetime is over. The renderer also draws a short core burst in the light field and a warm `lighter` lift of the whole frame, both rising on the 100 ms glow kernel (nothing on the hit frame, peak 100 ms later, gone by half a second), the only full-frame luminance transient, capped at +0.05 mean luma under lowFlash. A renderer test asserts the flash budget: a hit frame and the frame 0.4 s later differ by at most 0.08 in mean luma under lowFlash while still differing at all.

[`src/render/signal-strip.ts`](../src/render/signal-strip.ts) owns the two readouts below the graph. [`layout.ts`](../src/render/layout.ts) fits their vertical geometry into the space above 80% of the frame height: `span = min(0.14 × height, 0.8 × height − graphBottom)`, bounded at zero, and `geometryScale = span / (0.14 × height)`. The scope rest line is `graphBottom + 0.028 × height × geometryScale`, the bar baseline is `graphBottom + span`, and the tallest bar is `0.082 × height × geometryScale`; waveform swing uses the same scale and is bounded by the space above the peak caps, including the widest emission stroke. For landscape, the scope rests at 72.0%, the baseline is 80%, and the maximum bar is 5.86% of frame height. Portrait and square use a 62.8% scope rest line, 74% baseline and 8.2% maximum bars.

[`src/render/spectrum-readout.ts`](../src/render/spectrum-readout.ts) area-samples 64 frequency bands per channel, preserving independent source bins at the default analysis resolution and supporting lower-resolution analyses. Its causal envelopes have a 32 ms attack, 22 ms inertia and release from 400 ms in bass to 120 ms in treble; the material retains its separate 32-band profile. Both stereo channels share each band's 98th-percentile ceiling pooled across L/R (floor 0.12), so quieter channel content stays quieter. `spectrumStripGeometry` lays two sets of 64 rounded bars across the graph's width, with a slight horizontal offset and complementary phases of the same scene palette, scaled by a section gain of 0.6..1. Each channel is composited at 50% opacity, including its emission copy. One palette-colored cap per frequency takes the maximum of the two independently held channel peaks: a peak is captured immediately, held for 0.2 seconds, then falls at 0.38 normalized units per second until a bar catches it. Peak history is reconstructed from analyzed audio timestamps, so forward, reverse and direct seeks agree without depending on previously rendered frames. The mono `normalizedBandsAt` helper retains its bass-kick lift for the surrounding embers; that lift is not injected into a silent stereo channel.

`oscilloscopePath` lays the frame's signed waveform along the floor with 257 points, tapered to rest at both ends, at unit shape with a swing set by the fast loudness envelope; `signalBandAt` adds the traces of the two previous frames at 45% and 20% alpha (re-read from the analysis, never kept from a rendered frame) and a treble-pulse glow. `drawSignalBand` paints the band on the main canvas as pigment and a flatter, wider copy into the emission field so the bloom lays a soft coloured glow above the strip; nothing it draws enters the graph region.

[`src/render/ember-bokeh.ts`](../src/render/ember-bokeh.ts) floats soft discs of the cover's own light through the room. `createEmberPlan(seed, count)` splits `visual.bokehCount` embers into a far plane (12/28 of them, under the sculpture's bloom) and a near plane (in front of everything but the credits), each with a rest position, depth, radius, colour index, spectrum band and phase; the eight smallest of every 28 also sparkle with the raw treble pulse. `emberPoseAt` integrates the rise from absolute time and the body clock (faster in loud passages, no jump when energy steps) with an analytic wrap, sways on the drift clock, follows the graph camera's pan and the cover's Ken Burns offset at plane-dependent rates (near 1.7× / 1.4×, far 0.5× / 0.6×), pulses its alpha with its own normalised frequency slice and the section (the original 32 ember assignments area-average across all 64 readout bands, keeping high-frequency embers on high frequencies), swells near embers on the kick, dims 85% inside the credit lockup ellipse and caps alpha at 0.6. `drawEmbers` paints one plane as radial-gradient discs with screen blending. Colours come from the cover's 32 brightest saturated pixels (or the two accent swatches without a cover), lifted to read as light.

[`src/render/frozen-cloud.ts`](../src/render/frozen-cloud.ts) plans sparse, bass-weighted sculpture captures with at least three seconds between events, a 7.5-second lifetime and at most three live ghosts. Each event fixes the sculpture's geometry, textured skin, spectrum lighting, camera and colors at its capture timestamp. [`src/render/frozen-cloud-layer.ts`](../src/render/frozen-cloud-layer.ts) renders a small snapshot surface from that timestamp and caches it by source analysis and event identity; it is not sampled from whichever frame happened to render previously. Absolute event age drives a perspective expansion from 1 to about 2.22 as the ghost approaches the viewer. Opacity rises gently over 0.6 seconds to at most 0.20, then decays; stronger blur and fixed-mask erosion develop after 1.1 seconds. The ghosts are screened behind the live sculpture, with the credit mask applied after expansion and softening. The layer was measured before the last simplification and kept: at peaks it moves one to two percent of the frame's pixels by more than 16 levels. Forward, reverse and direct seeks recreate the same frozen material, impression and fade, including after cache eviction.

[`src/render/surface-fragments.js`](../src/render/surface-fragments.js) supplies the shared CPU/GPU plan for sparse surface peeling. It reuses the bass-capture schedule and creates 18 deterministic candidate islands in the original periodic surface coordinates, before the photograph's UV mirroring. A gently ragged elliptical coverage function wraps across both seams. Each renderer selects up to four exposed patches per burst from its own mesh; at most three bursts are active. Shared analytic poses start with zero drift velocity, then peel, tumble and approach the viewer with separate seeded momentum. The patches preserve their captured geometry, material colors and lighting as they become progressively blurred and transparent, with every edge feathered by at least half a percent of the graph radius (about 1.2 px at 1080p). Their lifetime is 6.3 seconds. The same coverage removes matching pieces from the current skin and filaments, opening over 0.10–0.65 seconds and healing over 1.65–2.70 seconds. Bounded capture caches reconstruct missing events from absolute timestamps after a seek, keeping the effect independent of playback history.

[`src/render/artwork.ts`](../src/render/artwork.ts) prepares a local PNG, JPEG, WebP or AVIF image once, before the encoder opens. `--image` overrides `visual.imagePath`; a relative CLI path resolves from the working directory, while a relative config path resolves beside its JSON file. Empty `imagePath` leaves the procedural scene unchanged. SVG, URLs and data URLs are not accepted.

The preparation stage downsamples the crop to at most 768 pixels on its long edge, blurs it by 0.35% of its short edge, remaps luminance to `0.03 + 0.78 × l^0.95` (so the brightest pixels stay near 80% white) while keeping 85% of the chroma, and bakes three alpha fades into the texture: a hero hole of at most 42% behind the sculpture, a corner vignette of at most 45%, and a 40% shade inside the credit lockup ellipse. On a 192-pixel crop it measures two focal points (the luma-weighted centroid of the brightest tenth and the chroma-weighted centroid of the vivid pixels, each falling back to the centre) and samples up to 32 ember colours with a minimum spacing. `deriveArtworkMotion(section, kick)` gives zoom `1.06 + section × 0.12 + kick × 0.03` and opacity `0.80 + section × 0.14`; saturation is always 1 and `hueShift` zero. `coverCameraAt` pans between the two focal points over a 48-second sinusoid with a slow wander and a share of the graph camera's pan, clamped to the margin the zoom creates. `drawArtwork` draws the texture source-over with that camera, a little brighter before the sculpture has arrived; the renderer paints the palette's darkest swatch beneath it. The source image is never modified.

`PreparedArtwork.objectMaterial` separately retains the full source image at up to 512 pixels on its long edge, without the background crop, remap, hero attenuation or vignette, with a ~1.5 px relief blur so the skin's tiles read as pigment. Its actual RGB and alpha map onto the folded sculpture. The artwork material tag preserves photographic pigment during lighting instead of reducing it to scalar reflectance. The same object material is used for immutable ghost and fragment captures.

[`src/render/palette.ts`](../src/render/palette.ts) defines a shared `ScenePalette` for the complete scene. Artwork colors are extracted from the full image before any aspect-ratio crop, ignoring transparent pixels: after k-means, each centre is represented by the most chromatic real pixel within a small colour budget (falling back to the nearest pixel outside it), so a cluster of muted shades yields its pigment rather than its grey and grey covers keep their exact swatches. `accentSwatches` names the roles the swatches play: the most chromatic warm swatch (red through yellow), the most chromatic cool one (green through violet), the darkest and the lightest; a palette without one family falls back to its two most chromatic swatches and a grey palette points every role at swatch 0. `swatchFamilyDirection` gives the ring direction in which a gradient can spread from an accent without crossing the grey midpoint between two families. Interpolation, neutral highlights, desaturation and brightness changes preserve those source color families; a grayscale source remains grayscale. `liftSwatch` raises a pigment to a readable luma without mixing in white. Without artwork, `randomPalette` creates a reproducible two-family palette: an anchor, two neighbours 22–30 degrees away and two near-complements. Frame-level tests exercise monochrome and single-hue artwork during strong transients, checking for unrelated color leakage across the completed image.

### Materials and moving lights

[`src/render/material.ts`](../src/render/material.ts) owns coherent albedo, scalar height, unit tangent-space normals and roughness. [`scripts/generate-materials.ts`](../scripts/generate-materials.ts) processes the committed AI grayscale relief source, feathering its boundary into a deterministic periodic harmonic field. It exports four matching 512² PNG maps and an area-averaged 128² byte array in [`assets/materials/silk-height.ts`](../assets/materials/silk-height.ts). Normal vectors come from central height gradients with wrapped neighbors: +X is right, +Y is up and +Z points toward the viewer. RGB normal files encode each signed component as `component × 0.5 + 0.5`. Roughness and normal files are linear data textures.

`createMaterial(seed, size)` imports the packed source synchronously, uses a seed-stable periodic offset, and derives CPU maps once. `recolorMaterial(material, palette)` replaces its decorative albedo with source-palette pigment while preserving the height, normal and roughness maps. Runtime dimensions are bounded to 256², with 128² as the default; the generator accepts up to 2048² for exported assets. `createProceduralHeight` remains available as a deterministic source-independent fallback. `sampleMaterial` bilinearly samples repeating maps and renormalizes interpolated normals, accepting a reusable result object for the hot path. Matching source bytes, seed and dimensions produce matching maps; regeneration tests compare every exported file byte-for-byte. `createMaterialFromRgba` derives the object material from the cover: it blurs alpha-weighted luminance before deriving a weaker relief, preserves RGBA, uses higher roughness, and clamps image edges instead of repeating. This is an artistic interpretation of brightness, not inferred physical depth.

[`src/render/lighting.ts`](../src/render/lighting.ts) exposes `lightingAt(motion, time, seed, paletteHue, lowFlash, spectrum?, palette?)` and `shadeSurface(state, x, y, z, sample, out?)`. Absolute slow musical time moves the bass key and midrange fill; the fast clock moves a smaller treble rim. The key light's intensity is `0.22 + bass × 1.15` plus a pulse term; the blended bass input spans about 0.3 in quiet passages to 0.8 at peaks, so the light roughly doubles between them; exposure is `1.45 + sustain × 0.5`, so the skin sits above its own coloured halo. The palette supplies ambient and light colors at lightness 55–62 (no white mixed in), while the phase control changes their mixture within that palette. Pulse accents are luminance transients, so lowFlash halves them; the envelopes are never capped. Each point light has bounded intensity, color and distance falloff. Shading combines diffuse light with roughness-dependent Blinn specular, Schlick Fresnel and restrained rim light, then applies a bounded Reinhard tone map.

The optional FFT input adds a 32-sample colored environment-light strip. Fractional area averaging supplies its bands; bass bands spread over a wider region with stronger radiance, while treble stays narrow. Every shaded surface reflects its view direction around the perturbed normal to select a strip frequency. Three filtered samples broaden the reflection according to roughness, with a Fresnel contribution at grazing angles. Strip rotation is prepared once per frame, zero spectrum contributes no light, and lowFlash tempers its strength (0.40 instead of 0.52; a smooth environment reflection is not a flash). The same light state reaches the sculpture skin, the filament segments and, without a cover, the material light bed.

[`src/render/surface-signal.ts`](../src/render/surface-signal.ts) produces shared, bounded 32-bin spectrum and 32-bin signed waveform signals through fractional area averaging. The offline material and the browser visualization read these shared analysis features. The export readout derives its own 64 frequency bands directly from the analyzed spectrum. The spectrum shapes material relief and roughness with greater low-frequency weight; the oscilloscope changes normals and bends a reflected light ribbon across the curved surface.

[`src/render/audio-field.ts`](../src/render/audio-field.ts) keeps `audioFieldAt(analysis, time)`: a causal profile filters RMS into a fast 20 ms attack / 200 ms release envelope and a slower 280 ms attack / 1.2 s release envelope, and each of 32 frequency bands has a 32 ms attack followed by a 22 ms inertia filter, with release from 400 ms for bass to 120 ms for treble. The material, preview and floor oscilloscope retain these envelopes; the export spectrum strip uses its own 64-band profile, and its normalized levels also drive the embers; [`src/render/audio-field-geometry.js`](../src/render/audio-field-geometry.js) supplies the monotone cubic waveform sampler the strip shares with the browser and the corona geometry the WebGL preview still draws. Envelopes are evaluated analytically from absolute time and prior audio, so frame rates and arbitrary seeks follow the same response without borrowing future samples.

[`src/render/spectral-flow.js`](../src/render/spectral-flow.js) supplies shared waveform and spectrum ribbon geometry for Canvas export and the WebGL preview. Five history ages (1.4, 1, 0.65, 0.32 and 0 seconds) read their own historical signals. A nonlinear flow map carries those curves outward through a spatial blend of spiral and folded ribbon paths; a continuous slow mask changes the blend without preset cuts. Bass supplies the strongest displacement, mids bend the flow and treble adds finer detail. Age controls expansion, softness and fading. This is a bounded reconstruction of musical light history, with no previous rendered frame as input, so direct seeks and parallel frame rendering retain the same result. The flow uses the existing palette and leaves the cover, surface geometry and text outside its history.

[`src/render/spectral-flow-layer.ts`](../src/render/spectral-flow-layer.ts) evaluates the shared geometry from the existing musical envelopes and historical waveform/spectrum samples. Up to 30 closed paths of 97 points draw into a light surface at up to a 480-pixel frame scale, cropped to the graph region with blur padding. Each has a narrow pigment core and a broader soft glow; older cores blur as they fade. The six paths at each age share two reusable scratch surfaces for core and halo, so blur runs once per surface rather than per stroke, with at most ten image composites and fixed scratch storage. The light surface and each age batch are cleared before drawing, then the combined light is masked after blur and clipped again after upscaling, protecting the title lockup and separate readout band. It is composited over the room before the sculpture's emission, bloom, ghosts and live geometry.

The design takes inspiration from MilkDrop's separation of persistent warping and display-only composition in its [preset authoring guide](https://github.com/milkdrop2077/MilkDrop3/blob/main/code/resources/Milkdrop2/docs/milkdrop_preset_authoring.html), and MilkDrop3's simultaneous double presets described in its [README](https://github.com/milkdrop2077/MilkDrop3#readme). The spectral-flow equations and rendering code are original. This small layer imports no MilkDrop presets or shaders; the separate optional MilkDrop engine below uses the attributed Butterchurn preset collection.

[`src/render/surface-mesh.ts`](../src/render/surface-mesh.ts) connects the same Resonance points into a material skin beneath the bright filaments. Procedural silk samples every second strand and every third curve point for 36 × 80 shared-vertex quads; a photograph uses 72 × 120 quads to retain image detail. Faces are sorted by mean camera depth, and source alpha controls their opacity. Material normals, local spectral energy and waveform slopes shade those faces; curved spectrum and waveform reflections use the moving light colors at 85% under a cover. A photograph's shadow lift is only partly applied (a full `1/√luma` gain flattened the key light's contrast), so the skin keeps its relief at peaks. The mesh preserves the sculpture's morphing shape and graph bounds, keeping material and filament motion aligned.

`captureMaterialSurface` selects cell-center UVs before allocating, sorting or shading faces, then returns the original vertex references, display-graded RGB, alpha and UV centers. It shares the live skin's complete shading formula. The full source grid remains available for photo sampling and the tangent basis, so a detached patch retains its original texture position and relief. The optional `opacityAt` callback on `drawMaterialSurface` uses the same cell centers to create live tears. Filament masks split individual line segments at those openings and suppress tracers inside them. Captured pieces use their actual curved polygons, retaining an irregular silhouette as they turn in depth.

[`src/render/surface-fragment-layer.ts`](../src/render/surface-fragment-layer.ts) selects and caches the offline patches. A 96² projected depth guide rejects largely hidden folds; accepted patches have at least 80% area-weighted visibility. Oversized candidates shrink in both UV dimensions and are recaptured, retaining those same smaller descriptors for their live tears. Birth span is bounded to 0.8 hero radii, aspect ratio to 5:1, and local three-dimensional extent to 14% of the remaining camera distance. The capture copies each selected face's geometry, shaded pigment and alpha, then unprojects the exact birth camera. Analytic rigid rotation and forward travel act on those curved vertices. A reusable 384² scratch surface draws the reprojected, depth-sorted polygons before the shared blur (never below the edge feather) and opacity envelope. Credit clearance fades an approaching patch before its blur reaches the typography.

[`src/render/material-layer.ts`](../src/render/material-layer.ts) maintains a low-resolution diffuse light on the seeded material, capped at 192 pixels on its long edge and composited behind text and the live sculpture in no-cover mode only (under a cover it would lay a haze over the illustration's own pigment; without one, removing it moved the frame by about three levels, so it stays). [`src/render/surface-material.ts`](../src/render/surface-material.ts) gives filament segments a tangent basis derived from the actual camera-space geometry: the sampled tangent normal is transformed into that basis before evaluating the same lights, so highlights follow surface orientation instead of acting as a uniform color filter; on the strands the light only shades the pigment and adds a small gleam, never brightening past the swatch itself. `visual.lighting` and CLI `--lighting` set the contribution from 0 to 1, defaulting to 0.65; zero skips material lighting. The title and artist are drawn afterward and do not receive surface shading.

[`src/render/reactive-effects.ts`](../src/render/reactive-effects.ts) keeps the pure geometry of the spectral ribbon, which survives only as a faint copy in the emission field (the bloom spreads it into a diffuse iridescent halo around the sculpture; it was measured and kept), the lowFlash `visualTransient` helper and the dynamic grade's bloom and vignette scales.

[`src/render/layout.ts`](../src/render/layout.ts) computes conservative landscape, square, and portrait safe rectangles. Full-bleed layers (room, embers, grade) ignore these bounds. Credits use a symmetric safe rectangle centered at the full frame's `width / 2`, independently of the graph center; `creditLockupEllipse` is the ellipse (30% of the width by 11% of the height) inside which the cover is shaded and the embers dim. With artwork, the rounded thumbnail and left-aligned text form one horizontally centered group; their vertical centers align. Without artwork, each text line remains centered. `signalBand` places and vertically scales the readouts below the graph, ending no lower than 80% of frame height. The top 16% stays clear of the credit group, whose entrance starts at 18%; the bottom 20% stays clear of the sculpture and readouts. These conservative margins leave room for hover titles and playback controls without claiming a fixed overlay size across every player. Full-bleed atmosphere continues behind both areas without black letterboxing. Portrait and square graph profiles additionally reserve bottom and right space for social captions and action rails; their decorative readout band ends at 74%. Both Resonance and MilkDrop exports share this foreground layout.

The Canvas2D scene draws these stages in order (the names are the profiler's):

1. `signals`: the frame's `FrameState` and the surface-fragment schedule update.
2. `room`: with a cover, one opaque fill of the palette's darkest swatch at lightness 14 and the 768 px cover source-over with the section/kick zoom, Ken Burns drift and a third of the graph camera's pan as parallax, at opacity `0.80 + section × 0.14`; without one, the cached 10 Hz quarter-resolution nebula (palette-relative base, seven lobes, brighter at peaks) with slow breathing. Then the far ember plane (screen).
3. `flow`: the finite waveform/spectrum history, drawn on its own small light surface and composited inside the graph reserve.
4. `emission` (quarter resolution): the signal band's flat copy outside the clip; under the shared camera the hit core bursts and the core glow (travelling from the cool pigment at rest to the warm one at peaks); inside the graph clip the back and front filaments at every second strand and 1.25× width, the faint ribbon copy and the hit rings at triple width.
5. `bloom`: the three-copy bloom of that field with music-driven saturation, followed by the destination-in credit mask.
6. `ghosts`: without a cover the material light bed; then the frozen sculpture clouds, screened behind the live scene.
7. `composite`: the bloom added to the room (`lighter` under a cover, where screen would bleach the pigment; `screen` over the dark nebula).
8. `band`: the floor oscilloscope with its two trailing traces, then the overlaid 64-band L/R bars and their single shared row of falling peak caps, on the main canvas and off the graph camera.
9. `hits`, `skin`, `filaments` (inside the graph clip under the camera): the hit ripple rings behind everything, then the depth-sorted photograph or silk skin with spectrum and waveform reflections, back filaments, front filaments and tracers in the warm/cool pigments (source-over over a cover, screen over the nebula).
10. `fragments`: detached textured surface patches.
11. `embers`: the near ember plane in front of the sculpture.
12. `post`, `dither`, `vignette`: the overlay warmth tint of the whole frame, the rate-limited warm hit lift, the seeded luminance dither (13 quarter-resolution white sheets with alpha 0..64 added at `visual.grain`, nearest-neighbour, 12 Hz cadence), and the palette-tinted vignette in no-cover mode only.
13. `typography`: the centered thumbnail, title and artist lockup, drawn last and untransformed; after its 0.65 s entrance it is painted once into a sheet and composited.
14. `readback`: `getImageData` to the encoder.

The graph clip spans `y 32–70%` in landscape (centered at `y 51%`) and `y 30–60%` in portrait and square output. Landscape layouts reserve top and bottom player chrome; portrait and square layouts additionally shift the graph center left and reserve a right action rail. The sculpture, its bloom and the hit rings share this graph layout. The complete credit group remains centered in the full video: its separate upper region spans `x 8–92%` for landscape and square, or `x 12–88%` for portrait. Long title and artist strings are measured and uniformly reduced to fit the available width after allowing for the thumbnail and gap, within that symmetric safe region.

A semibold title sits above a smaller medium-weight artist line, with tight tracking. Both stay near white and retain full opacity after a brief entrance; the letter forms remain sharp. Wide, very soft glyph shadows and the cover's baked credit shade provide contrast over the continuous cover image, with no full-width dark stripe or rectangular shadow clip. The optional cover thumbnail spans at least the complete text-block height and uses the ungraded source image in a rounded crop with a soft shadow. It shares the credit entrance and final output fades. The two lines are sized together to fit the available height, including entrance motion, and remain readable in small landscape and portrait previews. The lockup stays centred for the whole track.

Per-analysis caches (conductor profile with its section-level and warmth prefix sums, scene-dynamics states, music-motion integrals, the hit plan, the readout's band ceilings and peak history) are keyed by analysis object identity in `WeakMap`s. The nebula cache checks analysis identity as well as source metadata and the frame bucket. Frozen snapshot and fragment caches also respect analysis identity and retain a bounded set of event surfaces; evicted captures can be recreated from their capture timestamps. Current emission is rebuilt from scratch on every render, and the bloom is composited separately so it remains aligned with the sculpture during camera motion and direct seeks.


### Optional MilkDrop export

`visual.engine: "milkdrop"`, or `--engine milkdrop` on `render` and `clip`, dispatches to [`src/milkdrop/export.ts`](../src/milkdrop/export.ts) after the shared input, analysis, artwork and delivery validation. The default remains `resonance`. Butterchurn 2.6.7 and butterchurn-presets 2.4.7 are pinned; their selected presets and MIT notices are documented in [third-party.md](./third-party.md). This is a MilkDrop 2-compatible path, with no MilkDrop3-specific shader or `.milk2` loader.

`visual.milkdropPresets`, or comma-separated `--milkdrop-presets` IDs, supplies a candidate pool. Configuration validation rejects unknown, empty and duplicate IDs. A single ID selects that exact preset; multiple IDs select one member for the entire song, with no cycling or transitions between presets. An empty selection uses the eight `MILKDROP_DEFAULT_PRESET_IDS` in standard mode. The catalogue also includes `tunnel-race`, `mandelbox-explorer` and `fractal-descent`, using only built-in framebuffer, blur and noise textures. Automatic MilkDrop render seeds still include the configured IDs and their order; explicit seeds keep the foreground and palette stable for comparisons.

[`src/milkdrop/plan.ts`](../src/milkdrop/plan.ts) chooses exactly one preset from the source audio identity and the configured `visual.seed`. This choice is independent of excerpt start, duration, analysis/render frame rate and output resolution, rather than using the general render seed that includes output settings. A full-song render and independently rendered clip therefore select the same preset for a matching seed and candidate pool. The standard automatic candidate IDs are `vortex`, `ribbons`, `cosmic-dust`, `fog-tunnel`, `julia-fractal`, `plasma`, `folded-tunnel` and `moebius`. The schedule contains one entry at simulation frame zero, and the exporter prints the selected preset's ID and original name.

The plan warms up at most four seconds before the requested start, rounded down to complete simulation frames. Its `simulationStart + outputStartFrame / fps` equals the requested start, including fractional starts; `simulationFrames` includes that preroll plus the output frame count. This deliberately bounds excerpt cost. It does not reconstruct the framebuffer history of a whole-track render, so an independent clip and the equivalent full-song section need not match.

The backend finds Chrome/Chromium on the system or through `VISU_CHROME_PATH`, then `src/milkdrop/chrome.ts` launches a fresh temporary headless browser and controls only that process through the Chrome DevTools Protocol. It does not attach to a user session or profile. Bun bundles [`src/milkdrop/browser.js`](../src/milkdrop/browser.js), and a temporary loopback server exposes only the job's bundle, PCM, optional cover and ordered raw-frame endpoint behind a random path prefix. No media is sent to an external server. GPU initialization completes before the encoder opens the output; browser and server cleanup run on success and failure. Browser cleanup also closes its owned stderr stream, so background Chrome helpers that inherit the pipe cannot keep the export command alive after saving.

A separate FFmpeg decode supplies 44.1 kHz stereo float PCM because Butterchurn's offline frequency analysis assumes that rate. Each frame receives the preceding 1,024 samples as unsigned mono/left/right byte arrays, with silence before the simulation begins; Butterchurn performs its own FFT and audio envelopes. The browser installs a seeded random stream before constructing the engine, loads cloned preset data, and supplies a fixed frame clock in place of Butterchurn's smoothed wall-clock estimate. Native framebuffer feedback advances once per simulation frame. The selected preset therefore evolves on the fixed audio clock even if export runs slower or faster than playback.

The browser's final compositor remaps preset light to the exact `ScenePalette` used by the foreground. After normalizing a swatch's peak channel, it mixes 32% of the swatch's own luminance into RGB, preserving hue and neutral palettes. A 48% opacity factor precedes the screen blend with the prepared cover, so black preset pixels do not dim the photograph. Feathered masks attenuate the light by up to 60% behind the sculpture and 78% behind credits; the cover and foreground keep their own color treatment. Low-flash mode further reduces this layer's strength; no global flash-bound guarantee is made for the third-party presets. This compositor revision uses the `milkdrop-2` automatic-seed namespace, leaving Resonance seeds unchanged. GPU readback is flipped into top-down RGBA and posted one frame at a time. The browser control connection deliberately leaves the Network domain disabled, preventing large raw uploads from being duplicated into debugging events. Each request waits for Canvas composition and encoder backpressure before the browser advances. The encoder waits with temporary drain/error/close listeners and removes them after each write; racing every frame against a lifetime exit promise retains completed frame buffers and can exhaust memory on full songs. `VisualizerRenderer.render()` accepts that external background while retaining the existing sculpture, signals, ghosts, fragments, embers and typography. The normal encoder supplies resolution, H.264/AAC settings, metadata and synchronized fades.

Repeated jobs share seeded preset choices, fixed stepping and PCM windows in the same browser/GPU environment. Unlike the default Canvas renderer, the feedback engine cannot render an arbitrary frame independently of its preceding simulation. Cross-GPU byte equality is not guaranteed. `lighting:preview` remains a separate Resonance preview and does not run this export engine.

### Promo composition

`visual.mode: "promo"`, or `--mode promo` on `render` and `clip`, selects the artwork-led promotional composition and implies `visual.engine: "milkdrop"`. Config parsing accepts partial projects so subsequent CLI overrides and audio tags can fill their credits. After that enrichment, `validatePromoRequirements()` requires a nonblank local image path, song title and artist. Promo titles do not fall back to the audio filename. `renderVideo()` repeats this validation before file or encoder work and normalizes direct API requests to MilkDrop without mutating the caller's config. Standard mode retains optional cover/title/artist values and its existing engine selection.

Promo extracts the full cover's existing `ScenePalette`, selects one preset from the `tunnel-race,mandelbox-explorer` pool by default and honors explicit `visual.milkdropPresets` candidate pools. The prepared artwork keeps a larger ungraded thumbnail for the prominent cover; its requested size is half the internal short edge, bounded to 256–1024 pixels. The background uses actual Butterchurn feedback mapped into this palette with extra darkening for legible foreground art and text. The shared 60 fps stepping, PCM delivery, browser lifecycle and H.264/AAC encoder remain unchanged.

The promo foreground uses the approved Airy gallery (C) layout. The cover, credits and separate waveform form a single group centered in both axes. With φ = (1 + √5) / 2, the horizontal gap is `coverSize / φ²` and the right column is `φ × (coverSize + gap)`. At 1920×1080 this gives a 432-pixel cover, about 165 pixels of gap, and a 966-pixel right column. Narrower formats scale the group to stay inside the side margins. Both credit lines start at 113.4 pixels at Full HD. Bundled Cormorant Garamond at weight 600 and Manrope at weight 500 are registered under private Canvas family aliases for the title and artist, respectively; the unmodified variable TrueType files and their SIL OFL 1.1 notices are in `assets/fonts/`.

The renderer fits title and artist to one shared font size, measures their actual ink (including bearings), then aligns the title's visible top edge with the cover. Each title and artist line is centered on the waveform's horizontal midpoint using its visible ink bounds, so differently sized words share one axis. The background's quiet mask follows the resulting centered credit bounds. Vertical gaps derive from the fitted font size using φ² and φ⁴. The full cover/credits/waveform bounds determine the centered group's placement; wrapped credits reduce both fonts together to keep the group above the reserved spectrum region. Both lines use neutral ink and soft glyph shadows. The signal renderer and MilkDrop's soft cover and credit masks use this final fitted geometry.

The waveform is confined to the right column with a maximum peak-to-peak range of 68% of the cover height; its actual excursion follows the fast loudness envelope and its tapered ends stay on the baseline. The two 64-band L/R spectra overlap at 50% opacity each, use complementary cover-derived palette phases and a small horizontal offset, and share one peak cap per band using max(L, R). The analyzer uses 8% outer horizontal margins, grows upward from a baseline at 94% of the frame height and leaves the bottom 6% for player controls. Its height adapts to the foreground above it, reserves at least 12% of the frame and never exceeds 30%. Promo uses a separate readout timing profile: bars attack in 8 ms with 5 ms of inertia and release over 90–45 ms from bass to treble, while peak caps hold for 0.3 seconds and fall at 0.22 of normalized height per second. The standard readout timing is unchanged. Low-frequency bars have the greatest travel; the band-position gain tapers to 75% at the highest band, and zero-energy peak caps are transparent. The standard sculpture, orbiting layers and upper credit lockup are omitted.

Automatic promo seeds add the `promo-1` namespace to the MilkDrop seed inputs. Standard render seeds and explicit seeds remain unchanged; preset choice uses the separate song-based key described above. Default output suffixes are `.promo.mp4` and `.promo.clip.mp4`, keeping promotional versions separate from ordinary renders. `render:promo` is a CLI convenience; the same config works for full tracks and automatically selected portrait clips.

### YouTube thumbnails

The `thumbnail` CLI subcommand and `bun run thumbnail` script produce standalone 3840×2160 JPEGs below 2,000,000 bytes through [`src/render/thumbnail.ts`](../src/render/thumbnail.ts). The still composition uses the cover-derived palette, darkened artwork background, prominent cover and bundled promotional fonts. It does not start Butterchurn, analyze audio or render video.

[`src/thumbnail-command.ts`](../src/thumbnail-command.ts) plans either a single song or the WAV files directly inside a directory. A cover must have the same stem, ignoring case, and one of the supported raster extensions; ambiguous matches and case-colliding song names are errors. Single-song `--title`, `--image` and `--output` overrides are rejected for directory jobs, where `--output-dir` controls the shared destination. Defaults are `<song>.youtube.jpg` and `<folder>/thumbnails/<song>.youtube.jpg`, respectively. Explicit artist/title strings are normalized for whitespace while preserving case. When an explicit artist is supplied, the title defaults to the filename and no metadata process is needed. Otherwise the existing FFprobe metadata reader supplies missing credits, with a filename fallback for the title only.

The planner checks every input's readability, decodes covers to catch corrupt artwork and validates all destinations before returning jobs to the renderer. Existing outputs require `--overwrite`; symbolic-link destinations, including dangling links, are always rejected. Canonical paths and file identities protect all input songs and covers, including symlink and hard-link aliases. This prevents a missing cover or existing output late in a batch from leaving earlier outputs behind. Unexpected runtime failures can still leave already completed thumbnails. JPEG encoding and final size checks belong to the renderer and are shared by direct API callers.

### Live visualization preview

[`src/preview/lighting-server.ts`](../src/preview/lighting-server.ts) provides `bun run lighting:preview -- <song>`. [`src/preview/lighting-mesh.js`](../src/preview/lighting-mesh.js) constructs a periodic 64 × 192 mesh with the Resonance ring/orb/flower/knot morph clocks, 3D precession, broad bass folds and fine treble motion. [`src/preview/lighting-lensing.js`](../src/preview/lighting-lensing.js) derives a background lens from reduced-resolution captures of the actual projected GPU sculpture. The cover shader converts the resulting field gradient into a bounded radial/tangential offset, capped at 6.5 pixels per 1080-pixel short edge. It samples both image color and luminance relief at that displaced coordinate, with fixed screen-space credit and edge protection. Premultiplied artwork sampling keeps transparent padding from introducing hidden colors. The export no longer bends the cover; its Ken Burns camera replaced the lens.

[`src/preview/lighting-camera.js`](../src/preview/lighting-camera.js) supplies one absolute-time camera for the mesh, audio field, glow center and frozen capture centers. This gives the sculpture more screen space while easing framing changes around larger folds; historical captures use the same guide. [`src/preview/lighting-glow.js`](../src/preview/lighting-glow.js) captures fresh sculpture emission into a quarter-size texture, capped at 512 pixels on its long edge; a 13-tap radial filter, gentle enlargement and rotation add soft light around the current contours. [`src/preview/lighting-particles.js`](../src/preview/lighting-particles.js) draws 160 seeded GPU points across four independent clocks. Forward perspective travel grows them into larger near bokeh with brighter soft rims and fine streak accents, with separate back/front passes and invisible flight resets. Glow and particles use source-palette colors and a final screen-space credit fade. These layers are rebuilt from time and signals rather than accumulated framebuffers.

The uniform timeline also carries the two RMS envelopes and 32 filtered frequency bands from `audioFieldAt`. [`src/preview/lighting-audio-field.js`](../src/preview/lighting-audio-field.js) draws the preview's spectrum stems, amplitude ellipses and waveform orbit around the object with thicker antialiased strokes: round-ended spectrum stems and continuous ribbons for the smooth joined curves. The export keeps those loudness envelopes for its floor oscilloscope and uses separate 64-band envelopes for its spectrum strip and peak caps.

[`src/preview/lighting-flow.js`](../src/preview/lighting-flow.js) samples the existing timeline at the five shared history ages and draws the shared spectral-flow paths behind the live sculpture. Joined GPU ribbons and soft edges keep their brightness even along curves; a small fragment shader supplies a narrow core and a wider glow. Historical samples never replace the current sculpture uniforms. Palette colours, a screen-space credit fade and edge protection keep the flow inside the scene, and material inspection modes omit it. [`src/preview/lighting-ghosts.js`](../src/preview/lighting-ghosts.js) captures the entire illuminated GPU sculpture into immutable RGBA textures at the same bass accents as the offline renderer. Historical timeline uniforms and feature textures are restored for each capture, then replaced with the current signals before drawing the live scene. The server supplies the shared capture plan and a 30 Hz sampling of its optical envelope, so both renderers use the same lifetime, perspective approach, fade and erosion timing. At most three reduced-resolution textures are cached; seeking or resizing reconstructs missing captures from their original timestamps. [`src/preview/lighting-fragments.js`](../src/preview/lighting-fragments.js) freezes the historical timeline uniforms and UV descriptors for exposed surface patches at those same sparse bass accents. Visibility selection considers surface orientation, projected separation and self-occlusion. ### 4. Encode

[`src/render/encoder.ts`](../src/render/encoder.ts) streams raw RGBA frames to FFmpeg with backpressure. FFmpeg applies the Lanczos delivery filter (a spatial resize only when internal and delivery dimensions differ), synchronized picture-to-black and audio-to-silence fades, then encodes H.264 High-profile video with BT.709 metadata, two B-frames, four references, and a fixed closed GOP. It seeks the original source audio to the same start time, resets its local timestamp, pads and trims it to the frame-quantized video duration, encodes stereo AAC-LC at 48 kHz with a 384 kbps target, and muxes an MP4 with fast-start metadata.

Audio is converted to a platform-oriented delivery profile: AAC-LC, stereo, 48 kHz, and 384 kbps. This conversion does not apply loudness normalization. The source audio is always mapped explicitly. Integration tests decode finished picture and PCM data to verify the full three-second fade slopes, black endpoints, silent endpoints, excerpt-local timing, and non-silent midpoint in addition to codec metadata. Additional native Full HD60 landscape and portrait tests count and decode every distinct input frame, check A/V duration within 2 ms, confirm H.264 High/yuv420p/BT.709 and AAC, and verify bitrate settings and faststart in the output file.

The longer clip E2E drives the public CLI with a synthetic song containing a known drop and a busy cover PNG passed through `--image`. It validates the selected lead-in and 30-second portrait export, then decodes a 360-pixel-wide frame to distinguish the colorful cover thumbnail from text ink, check readable title and artist lines, and verify that the combined credit group is centered. Artist-only ink samples keep picture-fade measurements independent of the cover. Cadence, A/V timing and source alignment, codecs, metadata and synchronized fades are also checked on the finished MP4.

The MilkDrop E2E runs both public commands through the real browser engine. It checks one held preset, nonblank moving frames, source-palette colors, credit separation and the same 30-second upload format and fades. Its separate transport regression uploads 600 native 1920×1080 RGBA frames with byte checks and delayed acknowledgements. This catches full-resolution transfer failures that a quarter-scale visual test would miss, while startup/evaluation errors and repeated cleanup exercise the private browser's lifecycle.

The promo E2E validates all three required inputs and renders a short stereo 640×360, 60 fps fixture through the public CLI and real MilkDrop engine. It checks preset selection, palette fidelity, cover and text placement, spectrum and player-control margins, source-audio alignment, separate channel frequency data, metadata, codecs and MP4 fast start. The stereo decode E2E checks real resampling, mono hash stability and legacy cache enrichment. Unit tests additionally cover shared channel scaling, out-of-phase signals, half-opacity compositing and max(L, R) peak caps, along with portrait/square/extreme-aspect layout bounds, silence, causal attack, falling peak continuity, arbitrary seeks, reserved spectrum-area pixel clipping and full-frame grayscale preservation.

The optional `RenderRequest.fadeInSeconds` and `fadeOutSeconds` override the two fades independently. Explicit fades are fitted proportionally when their sum exceeds the excerpt duration, so they never overlap. Without overrides the existing symmetric fade and half-duration cap apply. Timing and fades are validated before encoder creation; nonfinite start/duration values are rejected. `validateRenderAnalysis()` shares version, source-hash, band-count and frame-rate validation between encoding and CLI dry runs.

Requested durations are converted to a whole frame count once, before rendering and encoding. The reported duration, FFmpeg limit, and video frame count therefore share one value. Source-file hash verification lives in the render core, so library callers receive the same cache/audio mismatch protection as the CLI.

The default frame rate is 60 fps. Default and `final` renders work at 100% of the requested width and height, CRF 18 and the `fast` H.264 preset. A default Full HD job draws natively at `1920×1080`; the portrait equivalent is `1080×1920`. The optional `output.maxBitrateMbps` config field defaults to `16` and sets FFmpeg `-maxrate 16M -bufsize 32M`: a 16 Mbps video ceiling with a 32 Mbit buffer. Values from 0 to 200 are accepted; zero disables the ceiling. Actual average bitrate depends on visual complexity.

`--quality preview` selects half scale, CRF 22, `veryfast`, and an 8 Mbps ceiling with a 16 Mbit buffer. `--quality master` selects native scale, CRF 8, `slow`, and uncapped CRF encoding for an optional archive. All quality modes retain the configured frame rate; explicit `--fps` and `--render-scale` overrides take precedence. Omit `--quality` to retain custom encoding settings from the project config.

The upload choices follow [YouTube's recommended MP4/H.264/AAC settings](https://support.google.com/youtube/answer/1722171). Its 1080p high-frame-rate reference is 12 Mbps; this project's 16 Mbps ceiling allows additional headroom and is not a platform requirement. The Full HD60 portrait profile also fits [TikTok's media transfer specifications](https://developers.tiktok.com/docs/en/content-posting-api-media-transfer-guide): MP4/H.264, 23–60 fps, and dimensions from 360 to 4096 pixels.

## Reproducibility contract

A render plan is identified by:

- decoded PCM hash;
- input artwork bytes, when supplied;
- bundled material source bytes;
- explicit or automatically derived seed;
- analysis and renderer versions;
- selected engine, and pinned engine/preset versions for MilkDrop;
- output dimensions and frame rate;
- project visual settings;
- absolute frame time.

The current renderer version is **25** and analysis version remains **2**. In the default Resonance renderer, every pixel is a pure function of the cached analysis, absolute time, the seed, the configuration and the cover bytes: no state carried between `render()` calls depends on call order, and the per-analysis caches (the conductor profile with its section-level and warmth prefix sums, scene-dynamics states, music-motion integrals, the hit plan, the readout's per-band ceilings and peak history) only avoid recomputing identical data. The seeded plans are the filaments, the nebula lobes, the embers, the dither sheets, the material placement, the light phases and the frozen-cloud erosion noise; the per-cover data are the palette with its accent swatches, the focal points and the ember colours. Composition and motion are reproducible, including palette extraction or seeded palette generation, frozen-cloud and surface-fragment capture selection, fragment trajectories and healing tears, prepared background and object artwork, the cover camera, spectrum/amplitude envelopes and absolute-time light positions. A test renders cover frames at three times on fresh renderers after forward, reverse and direct seeks and requires byte-identical buffers.

The Resonance flash policy is part of the contract: `visual.lowFlash` defaults to `true`; geometry (camera zoom, sculpture size, bar height, ring radius, scope amplitude) is never capped in either mode; luminance transients are capped at `LOW_FLASH_TRANSIENT_CAP` (0.5), light pulses are halved, hit-ring light ramps in over 50 ms and caps at 0.45, the core burst caps at 0.5 and the full-frame lift at +0.05 mean luma; hits are rate-limited to one per 0.34 s by the cached plan; and a renderer test holds the mean-luma difference between a hit frame and the frame 0.4 s later to at most 0.08 under lowFlash. Pixel-identical output is guaranteed within the same pinned native runtime; standard-mode system fonts and codecs may vary slightly across platforms. Promo bundles its font files, but native rasterization and codec versions still affect cross-platform bytes.
